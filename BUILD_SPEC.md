# Harbor GRC — local-first build specification

## Product intent
Build a working, original, single-user local governance/risk/compliance application inspired by public Vanta capabilities. This is NOT Vanta, is not affiliated with Vanta, is not an exact clone, and must not claim certification, legal sufficiency, automated cloud monitoring, or AI features it does not implement. Public capability references: https://vanta.com/pricing ; https://vanta.com/trust-management-platform ; https://vanta.com/products/vendor-risk-management .

Primary surface: OPERATE (tables, work queues, focused detail/editing); overview is secondary MONITOR. No marketing hero, no invented metrics. Brand: Harbor GRC. Sidebar deep forest #172b27, main #f6f8f7, white surfaces, accent #147d64, ink #182824, muted #62736d, border #dfe6e2. Precise typography, compact accessible tables and small geometric mark. Use local/system fonts (no CDN). Original visual identity, not copied Vanta screens. Responsive desktop/tablet/mobile, keyboard focus, real loading/empty/error states, no dead buttons.

## Architecture / ownership
- Python 3.11 FastAPI server, sqlite3 persistent storage, files in data/uploads. Backend agent owns server/, tests/backend/, requirements.txt.
- React + TypeScript + Vite client. Frontend agent owns client/ (including package.json and its tests). Build client/dist; server serves it in production.
- Parent owns docs/, scripts/, deployment/, README, this specification, root metadata, independent acceptance tests. Do NOT change other owners' files without a demonstrated contract problem communicated in your final report.
- Production URL http://127.0.0.1:8765. Bind loopback only. Single local OS-user trust boundary; do not imply user-account authentication. Same-site session+CSRF and Host/Origin checks; no wildcard CORS. No external telemetry, API keys, or outgoing requests. All assets local after installation.
- API detailed below is authoritative. Use snake_case JSON. Do not spontaneously change contract to fit UI.
- Strict vertical TDD: one failing behavior test, run observe failure, implement, rerun green, repeat. Preserve brief RED/GREEN evidence in your own test log. Do NOT write every test then every implementation. Real temp SQLite DB and file paths in backend tests. Frontend unit tests can isolate pure helpers; use integration/browser checks for UI when practical.

## API transport
`create_app(data_dir: Path | str | None = None)` exported from server.app; `python -m server` launches uvicorn on 127.0.0.1 and PORT=8765, reads HARBOR_DATA_DIR (default project/data). `GET /api/health` -> {status:"ok", version:"0.1.0", storage:"sqlite"}.
`GET /api/bootstrap` -> {workspace, csrf_token, counts, frameworks, capabilities}. Sets HttpOnly SameSite=Strict local session cookie. Every POST/PATCH/DELETE must include session cookie and `X-CSRF-Token` from bootstrap. Browser fetch same-origin credentials. Reject hostile Origin/Host and cross-site Fetch-Metadata. Permit exact development localhost origins 5173 and production 8765. API errors: {detail:string} with correct 4xx/5xx.
`workspace`: {name:"Your workspace", organization:"", owner:"", description:"", trust_title:"Security at our organization", trust_description:"", trust_policy_ids:[], trust_evidence_ids:[]}.
`PATCH /api/workspace` merge allowed fields; data backed by SQLite.
`GET /api/schema` -> {resources:{[resource]:{label,singular,statuses:[string],fields:[{key,label,type,required?,options?,readonly?}]}}}. Type is text|textarea|number|date|select|multiselect|boolean|json|email|url. This powers dynamic forms but UI must have purpose-built detail panels for policy content, questionnaires, access reviews, and evidence upload.
`GET /api/{resource}?q=&status=&owner=&framework_id=` -> {items:[record],total:number} (all filtered records; maximum 5000 reasonable). `GET /api/{resource}/{id}` -> record. `POST /api/{resource}` -> created record HTTP201. `PATCH /api/{resource}/{id}` -> updated record. `DELETE /api/{resource}/{id}` -> {deleted:true}; missing IDs 404; dependent links must be cleaned or deletion blocked clearly. Validate input types, lengths, dates, enums, references (invalid linked IDs ->422). Generic resource names strictly allowlisted. Never interpolate user input into SQL. Reject unknown fields on writes.
Common record fields: id (server UUID), title (required, 1..240), description (default ""), status (resource enum), owner (default ""), due_date (nullable ISO YYYY-MM-DD), tags (string array, default []), created_at, updated_at (server UTC ISO timestamps). Each resource has only its explicit fields below plus common fields.
Read-only IDs/timestamps/derived fields rejected on writes; clients must not echo the full server record on PATCH.

### Resources and fields (status first entry is default)
- `frameworks`: statuses not_started,in_progress,ready; code, version, source_url, guidance. No licensed standard text. Support custom frameworks. No automated certification determination.
- `controls`: statuses not_started,in_progress,implemented,not_applicable; code, category, framework_ids (array), implementation (text), evidence_ids (array), policy_ids (array), frequency (annual,quarterly,monthly,continuous). Default annual.
- `policies`: statuses draft,in_review,published,archived; content (long text, editable plain markdown rendered safely), control_ids (array), review_date (date), version (readonly integer), approved_at (readonly), approver (text). Content changes create immutable version rows and increment version. Published policy edited -> draft. Publication via action below.
- `vendors`: statuses intake,in_review,approved,rejected,offboarded; website(url), category, tier(low,medium,high,critical; default medium), data_access(text), contact_email, renewal_date(date), review_date(date), likelihood(1..5 default3), impact(1..5 default3), residual_likelihood(1..5 default2), residual_impact(1..5 default2), assessment_notes(text), evidence_ids(array).
- `risks`: statuses identified,assessing,treating,accepted,closed; category, likelihood(1..5 default3), impact(1..5 default3), residual_likelihood(1..5 default2), residual_impact(1..5 default2), treatment(text), control_ids(array), vendor_id(nullable reference). Derived inherent_score and residual_score are readonly = product. Show 5x5 heatmap calculated from these records.
- `evidence`: statuses collected,in_review,approved,expired; source(manual,link,import; default manual), url, control_ids(array), collected_date(date), expires_date(date), filename/file_size/sha256 readonly nullable. File upload endpoint below; metadata-only evidence via normal create. Expiry checks never present old approved evidence as fresh.
- `audits`: statuses planning,in_progress,in_review,complete; framework_id(nullable), period_start,period_end(date), auditor(text). Audit request records linked separately.
- `audit_requests`: statuses open,in_progress,submitted,accepted; audit_id(required reference), control_id(nullable), evidence_ids(array).
- `tasks`: statuses todo,in_progress,blocked,done; priority(low,medium,high,urgent; default medium), related_type(text), related_id(text), checklist(array of {text,done}). Related type/id either both empty or reference valid resource+id.
- `people`: statuses onboarding,active,offboarding,inactive; email, department, role, start_date(date), training_completed(bool default false), training_due(date), acknowledged_policy_ids(array). These are personnel records, NOT app login accounts. Acknowledgment is an owner-recorded attestation, not a signature or proof of identity.
- `assets`: statuses active,in_review,retired; category(hardware,software,cloud,data,other; default hardware), identifier, system, encrypted(bool|null), mfa_enabled(bool|null), last_reviewed(date). These are manually reported attributes, NOT machine-collected tests.
- `access_reviews`: statuses draft,in_progress,completed; system, reviewer, entries(array of {id,user,access,decision:pending|keep|revoke,notes}). Server generates missing entry IDs. Completed requires every entry decision not pending and at least one entry. Record decisions only; do not claim revocation executed.
- `questionnaires`: statuses draft,in_progress,in_review,complete; customer, questions(array of {id,question,answer,status:unanswered|draft|approved,source_ids:[]}). Server generates missing question IDs. Complete requires all questions approved and at least one question.
- `exceptions`: statuses requested,approved,rejected,expired; control_id(nullable), reason, expires_date(date), approver. Expiring exception cannot silently count compliance.

## Specific workflows
`GET /api/dashboard` -> {counts, readiness:{implemented,total,percent}, framework_readiness:[{id,title,code,implemented,total,percent}], open_risks, high_risks, overdue_tasks, expiring_evidence, upcoming_reviews:[{resource,id,title,date}], activity:[...], risk_matrix:[{likelihood,impact,count}], attention:[{resource,id,title,reason,severity}]}. All counters derived from DB; not_applicable excluded from readiness denominator. UI robust to no data. Readiness = recorded implementation, NOT certification.
`GET /api/search?q=...` -> {results:[{resource,id,title,status,snippet}]}; safe result cap.
`GET /api/activity` -> {items:[{id,action,resource,record_id,title,created_at,details}],total}. Append-only from writes, including policy publishing and monitoring.
`POST /api/policies/{id}/publish` JSON {approver:string}; nonempty content+approver required. `GET /api/policies/{id}/versions` -> {items:[{version,content,created_at}]}; export via `GET /api/policies/{id}/export` markdown attachment.
`POST /api/evidence/upload` multipart file and optional fields title, description, control_ids (JSON encoded array), expires_date. Max25MB; return evidence record. UUID internal filename; stream upload; sha256; default filename basename only. `GET /api/evidence/{id}/file` -> attachment safe Content-Disposition, application/octet-stream and nosniff. Never serve uploads as static executables. Link to controls bidirectionally or document direction consistently.
`GET /api/monitoring` -> {checks:[{id,title,description,status:pass|fail|not_run,finding_count,last_run,findings:[{resource,id,title,reason}]}],last_run}. Built-in local checks: unassigned controls, expired evidence, overdue policy reviews, overdue vendor reviews, overdue tasks, assets explicitly reported unencrypted, open access-review decisions. Missing data must be labelled not assessed, not silent success. `POST /api/monitoring/run` returns same shape; real local DB evaluation, persist run history; log to activity. Clearly label "Local record checks — no connected cloud telemetry".
`POST /api/questionnaires/{id}/suggest` -> questionnaire record. Deterministic keyword-based suggestions from PUBLISHED policies only; source IDs stored, nonempty existing answers not overwritten; suggestions status=draft and require review. Call it "Suggest from policies", not AI. If no relevant source no invented answer.
`GET /api/export/{resource}` -> CSV of records; protect spreadsheet formula injection on every string value. `POST /api/import/{resource}` multipart file CSV + dry_run string true/false; allowed simple modules: controls,vendors,risks,tasks,people,assets. Respond {imported,preview:[records],errors:[{row,message}]}; dry-run no writes; invalid row ->422 with clear error, no partial import. Array fields accept JSON arrays. UI CSV sample/template can use export schema; import modal explains matching headers.
`GET /api/backup` -> ZIP containing consistent SQLite snapshot, evidence files, manifest with version. No restore API. Parent supplies offline restore/backup tools.
`GET /api/audits/{id}/export` -> ZIP scoped audit report, mapped controls/policies, linked evidence and requests, manifest. No unrelated confidential records.
`GET /api/trust` -> {workspace:{name,organization,trust_title,trust_description},policies:[published selected metadata],evidence:[approved nonexpired selected metadata]}; local-only preview. `GET /api/trust/export` -> ZIP of only selected published policies and approved unexpired documents plus HTML/markdown summary. Selection validates actual IDs. No external publication or fake access gates.
`GET /api/integrations` -> {items:[{id,title,status,description,capabilities:[...]}]}. Manual CSV and local file upload available; Google Workspace,AWS,GitHub,Slack etc explicitly not_configured/not_implemented, not fake live connectors. No secret-entry UI for unimplemented integrations. Explain optional future integrations clearly.

## Starter library / first run
Seed original, clearly marked "Starter guidance — review for your scope" content: 5 framework reference shells (SOC 2, ISO 27001:2022, NIST CSF 2.0, GDPR, HIPAA); roughly 24 original generic controls with mappings (illustrative, not an authoritative licensed crosswalk); 8 substantive editable draft policy templates (security, access control, incident response, risk management, vendor management, data handling/retention, business continuity, change management). No invented employees, vendors, evidence files, passed tests, or historical activity. Do not mark anything implemented/published automatically. Policy placeholders must clearly invite tailoring. Idempotent seeding independent from service restarts. Readiness starts zero. No paywall copyrighted full standard reproduction.
